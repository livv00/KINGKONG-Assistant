## 1. 背景与目标（Why）
用户现场存在两种批次的灯光电柜设备：

- **老批次（硅箱协议）**：收发 UDP 2021，单包 530 字节；
- **新批次（新版电柜协议）**：发送 2023 / 回传 2021，短报文 `aa6a...aaa6`。

软件发货给客户时无法确定客户现场是哪一批，因此需要**「同一个IP，两套协议同时发送」**，让新/老批次设备各自收到自己能识别的包并执行动作。同时用户明确要求「电柜管理窗口**必须与主界面主线（音乐/控台/直播）完全隔离**，不得影响主线任何行为」，因此架构上采用「独立 BrowserWindow（渲染进程隔离）+ UDP 处理全部放在主进程（非阻塞）」方案。

---

## 2. 需求范围（What's in / out）
### In Scope
1. 主界面右上角新增入口按钮「⚡ 电柜管理」，位置在「悬浮窗按钮」**前面**。
2. 点击按钮打开一个**独立 BrowserWindow（cabinet-manager.html）**，UI 实时跟随当前主题（dark/light/cute/cool 四种 + 主题色）。
3. 独立窗口内可以「添加 / 删除 / 编辑电柜」：每个电柜包含 IP、名称、开关数（12/18/24/30/36，默认12）、电柜编号(1-255，默认1)、硅箱序号(1-255，默认1)。
4. 每个电柜生成 N 个开关按钮（每行6个），每个按钮可重命名、改颜色、改路号（默认=按钮下标+1）。
5. 按钮交互：**单击切换（关↔开）**；按钮状态**纯回传驱动**（收到设备回传后才更新UI）；发送后 1000ms 没收到回传则闪烁黄框提示超时，但**不修改 UI 状态**。
6. 一键全开 / 一键全关：分别使用两套协议的"一键指令"（电柜一键 + 硅箱顺序逆序模式）。
7. 新老兼容：任何一次动作（单路/一键/查询）**永远同时发送两套 UDP**：新版电柜→`<ip>:2023`；硅箱→`<ip>:2021`。
8. 所有配置持久化到 localStorage（窗口重启 / 软件重启后仍在）。
9. 严格防卡死：
   - 收包长度阈值（<6 或 >1600 丢弃）；
   - 收包无 while 循环，每次 message 回调只处理 1 个包；
   - 发送 pending 队列有长度上限（5000）。

### Out of Scope
- 主界面（index.html）不渲染任何电柜 UI，不参与任何 UDP 发送/接收 IPC（完全隔离）。
- 不做"多个电柜联动/级联编排"（当前用户没提）。
- 不做日志/历史记录（用户没提）。
- 不做电柜数据与音乐/控台绑定（后续如果提"场景一键连电柜"再做）。

## 3. 架构与技术选型（How — Architecture）

### 3.1 进程/窗口架构
```
┌───────────────────────────────────────────────────────────┐
│                     Electron 主进程 main.js               │
│                                                           │
│  UDP 层（全部在这里，非阻塞，不会卡 UI）：                    │
│  ├─ UnifiedRecvSocket：绑定 0.0.0.0:2021（reuseAddr）      │
│  │   ├─ 收包 → 长度分流解析（530=硅箱 / aa6a头=电柜）         │
│  │   └─ 解析结果 → 只 webContents.send 给 cabinetWindow    │
│  └─ 发送：同一 socket.send 分别发 2021(硅箱) / 2023(电柜)   │
│                                                           │
│  PendingList(上限5000) + 100ms 超时定时器                    │
│                                                           │
│  IPC：                                                       │
│  ├─ open-cabinet-window / cabinet-window-control            │
│  ├─ cabinet:get-config | cabinet:save-config                │
│  ├─ cabinet:send            | cabinet:query                 │
│  └─ cabinet-theme-sync（主界面切主题 → 同步给电柜窗口）       │
└───────────┬───────────────────────────────────────────────┘
            │ IPC（invoke / send）
            │
    ┌───────▼─────────────┐        ┌──────────────────────┐
    │  主窗口 index.html  │        │  电柜独立窗口         │
    │  (BrowserWindow #1) │─完全隔离▶  cabinet-manager.html│
    │  (不接触 cabinet)   │        │  (BrowserWindow #2)  │
    └─────────────────────┘        └──────────────────────┘
```

### 3.2 文件清单
| 文件 | 角色 |
|---|---|
| [main.js](file:///d:/TRAE%20LIVV/直播助手/main.js) | 主进程：UDP socket 生命周期 / 组包 / 解析 / 超时 / IPC / 创建 BrowserWindow |
| [index.html](file:///d:/TRAE%20LIVV/直播助手/index.html) | 主界面：只加一个「⚡ 电柜管理」入口按钮（悬浮窗按钮前），不做任何其他电柜逻辑 |
| [cabinet-manager.html](file:///d:/TRAE%20LIVV/直播助手/cabinet-manager.html) **（新建）** | 电柜独立窗口：完整 UI + 配置读写 + IPC 调用 + 状态更新渲染；和 console-connect.html 同级 |

> CSS/JS 内嵌在 cabinet-manager.html，不单独拆文件（沿用 console-connect.html 的风格）。

### 3.3 进程隔离严格规则（防止不小心"污染主线"）
- **index.html 不允许出现**任何 `ipcRenderer.invoke('cabinet:xxx')` 或 `ipcRenderer.on('cabinet-xxx')`。
- **main.js 里 UDP 收包回调 `socket.on('message')`**：**只给 cabinetWindow 发消息**，不允许 `mainWindow.webContents.send('cabinet-xxx')`。
- **localStorage**：`cabinetManagement.v1` 由 cabinet-manager.html **唯一读写**；main.js 不读不写 localStorage（通过 IPC 让渲染进程返回配置给它就够了）。

## 5. 数据流与持久化

### 5.1 配置 JSON Schema
localStorage key：`cabinetManagement.v1`

```json
{
  "schemaVersion": 1,
  "activeCabinetId": "cb_abc123",
  "cabinets": [
    {
      "id": "cb_abc123",
      "name": "1号电柜",
      "ip": "192.168.1.100",
      "switchCount": 12,
      "cabinetNo": 1,
      "siliconNo": 1,
      "buttons": [
        { "roadNo": 1, "name": "第1路", "color": "#ff6b6b" },
        { "roadNo": 2, "name": "第2路", "color": "#ff6b6b" }
      ]
    }
  ]
}
```

### 5.2 内存态（不存盘）
cabinet-manager.html 内存里额外维护：
```
cabinetRuntimeState = {
  [cabinetId]: {
    // 数组长度 = switchCount，值： 0关 / 1开 / -1未知(刚打开窗口没查过) / -2超时
    statuses: [0,0,...]
  }
}
```
打开窗口后：
- 读 localStorage → 渲染列表与按钮；
- 立即给 activeCabinet 发一次 `cabinet:query` → 等待真实设备回包 → 更新 statuses → 重绘。

### 5.3 按钮数变化的兼容规则（重要）
用户编辑电柜时改 switchCount：
- **变大（例 12→24）**：buttons 数组 `concat` 默认新元素（`roadNo = index+1`，name=`第N路`，color=`theme-color`）。
- **变小（例 24→12）**：先弹警告"后面12条按钮配置将被丢弃，是否继续？" → 确认后 slice(0, 12)。
- **cabinetRuntimeState.statuses**：同样同步 resize，新增位置填 -1。

## 6. UDP 协议与通信规范（逐字节对齐用户协议文档）

### 6.1 Socket 管理（main.js）
```javascript
let unifiedRecvSocket = null;

function ensureCabinetSockets(){
  if(unifiedRecvSocket) return;
  unifiedRecvSocket = dgram.createSocket({ type:'udp4', reuseAddr:true });
  unifiedRecvSocket.on('error', err => {
    broadcastCabinetError(`UDP 2021端口错误：${err.message}`);
  });
  unifiedRecvSocket.bind(2021, '0.0.0.0', () => {
    // 绑定成功
  });
  unifiedRecvSocket.on('message', onCabinetRecvMessage);
}
```

### 6.2 发送：永远两套同时发
对于每个动作：`{ ip, cabinetNo, siliconNo, road: roadNo|'all', action: 'on'|'off'|'query' }`：
```
→ 组装【新版电柜】Buffer → socket.send(buf, 0, buf.length, 2023, ip)
→ 组装【硅箱】530B Buffer → socket.send(buf, 0, buf.length, 2021, ip)
→ 推入 pendingList
```

### 6.3 新版电柜组包（逐字节）
- 单路：`aa6a 01 <cabinetNo> <roadNo> <actionByte> aaa6`（7B）
  - actionByte：on=0x02 off=0x00
- 一键：`aa6a 02 <cabinetNo> 00 <actionByte> aaa6`（7B）
- 查询：`aa6a 04 <cabinetNo> 00 00 aaa6`（7B）

### 6.4 硅箱组包（总 530 字节，前 15B 有效）
`Buffer.alloc(530, 0x00)`，设置：
```
buf[8]=0x63; buf[9]=0x00;
buf[10]=cmd;        // 查询0x01 / 开0x02 / 关0x03
buf[11]=siliconNo;  // 0x01..0xFF
buf[12]=road;       // 单路 0x01.. / 全部/查询 0x00
buf[13]=mode;       // 单路0x00 / 一键开0x02(顺序) / 一键关0x01(逆序) / 查询0x00
// buf[14] = 0x00 占位，其余 15..529 都是 0x00
```

### 6.5 收包分流（严格按文档 + 防卡死硬阈值）
```javascript
function onCabinetRecvMessage(msg, rinfo){
  // 硬阈值1：长度不合理直接丢
  if(!msg || msg.length < 6 || msg.length > 1600) return;
  try{
    if(msg.length === 530){
      parseSiliconPacket(msg, rinfo);   // 硅箱包
    }else{
      // 硬阈值2：帧头尾必须对
      if(msg[0]===0xaa && msg[1]===0x6a &&
         msg[msg.length-2]===0xaa && msg[msg.length-1]===0xa6){
        parseCabinetPacket(msg, rinfo); // 新版电柜包
      }
      // 否则：垃圾包，静默丢弃（不打log，防止刷屏卡死）
    }
  }catch(e){
    // 解析异常直接吞，绝不 throw
  }
}
```

### 6.6 回包解析 → 更新 UI
- **新版电柜 0x21（查询回包）**：
  - 柜号 = `msg[3]`
  - 状态起始 = msg[4]，最多 36 字节
  - 每字节 → `0x02=开(1)`、`0x00=关(0)`、其他→`-1(未知)`
- **新版电柜 0x01/0x02（控制原包回传）**：匹配 pendingList → 取 `{ cabinetId, roadNo, action }` → 更新对应 status。
- **硅箱包 byte14**：`0x01=关(0)`、`0x02=开(1)`、其他→`-1`；结合 pendingList 或 硅箱号/路号字段 匹配 cabinetId。

### 6.7 PendingList 与超时
```javascript
const MAX_PENDING = 5000;
let pendingList = []; // { ts, expireAt, cabinetId, road, action }
// 100ms 定时器扫 pendingList，expireAt 超时的 → cabinetWindow 发 cabinet-status-update(timeout:true)
```

## 7. IPC 接口清单（严格异步，避免同步阻塞）

### 7.1 主进程 handle（cabinet-manager.html → main.js）
| 通道 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `cabinet:get-config` | 无 | `{schemaVersion, activeCabinetId, cabinets}` | 让 main.js 也能拿到配置（main.js 本身不读 localStorage，通过这个 IPC 从渲染进程取，避免跨进程文件操作） |
| `cabinet:save-config` | configObj | `{ok:true}` | 仅作为"广播"让 main.js 内存缓存的配置更新；真正的写盘由 cabinet-manager.html 自己操作 localStorage |
| `cabinet:send` | `{cabinetId, road:1..N|'all', action:'on'|'off'}` | `{sent:true}` | 立即组两份 UDP 包发送，推入 pendingList，异步状态后续通过 push 事件回来 |
| `cabinet:query` | cabinetId | `{sent:true}` | 发查询包（电柜+硅箱两份） |

### 7.2 主进程 push 事件（main.js → cabinet-manager.html）
| 通道 | payload | 说明 |
|---|---|---|
| `cabinet-status-push` | `{cabinetId, type:'road'|'bulk'|'timeout'|'queryResult', ...}` | 实时更新按钮开/关或闪烁 |
| `cabinet-error` | `{code:'BIND_PORT_2021_FAIL'|'SEND_FAIL'|..., message}` | 在窗口顶部 toast 显示 |
| `cabinet-theme-sync` | `{theme:'dark'|...|'cool', themeColor:'#xxxxxx'}` | 主界面切换主题时同步给电柜窗口 |

## 8. 状态图（关键交互流程）
### 场景：单击某个开关按钮（从 0→开）
```
点击按钮
  → cabinet-manager.html 校验 cabinetId+roadNo 合法
  → invoke cabinet:send(action:'on')
  → main.js 组 UDP 电柜包 + 硅箱包 → 同时发送到 ip:2023 和 ip:2021
  → main.js push pendingList（expireAt=now+1000）
  → 等待回传：
      ✅ 1000ms 内收到任一有效回包 → 移除 pending → push cabinet-status-push(type:'road', status:1) → UI 把按钮点亮
      ❌ 超时 → push cabinet-status-push(type:'timeout') → 按钮闪黄框（但 status 仍然保持 0）
```

### 场景：一键全开
```
点一键全开
  → cabinet:send(road:'all', action:'on')
  → 电柜包：`aa6a 02 <cabinetNo> 00 02 aaa6` → :2023
  → 硅箱包：cmd=0x02 road=0x00 mode=0x02(顺序) → :2021
  → 等待回传，成功后 cabinet-status-push(type:'bulk', status:1, roads:'all') → UI 一次性点亮全部按钮
```

### 场景：主界面切换主题
```
主界面 applyTheme(theme, color)
  → 顺手 webContents.send(给 cabinetWindow 如果存在) cabinet-theme-sync
  → cabinet-manager.html 收到 → 写入 body[data-theme] + CSS var → 实时生效
```

## 9. 风险与缓解
| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 2021 端口被其他程序占用（例如客户现场已有老软件） | 无法收包 → 按钮纯黑、不亮，但用户以为成功了。 | bind 失败时弹 toast：「2021端口被占用，无法接收回传，只能下发指令。请关闭其他占用软件后重试。」，并在按钮旁提示"未知状态"图标。 |
| 发送超时率高（网络差/跨网段/加了路由器丢包） | 用户以为坏了。 | 超时按钮边框闪黄 + tooltip 提示「发送超时，建议检查网线/IP」，并允许点右下角"查询状态"手动刷新。 |
| 用户在多台电脑开了多个此软件 → 2021 端口绑定冲突 | 同第一条。 | reuseAddr 只能保证绑定成功，收包由操作系统分配；UI 上增加「本软件已准备就绪，但检测到 2021 被其他程序同时监听，回传可能不稳定」的温和提示。 |
| 电柜窗口打开后，主界面关了但电柜窗口没关 → 用户误以为程序卡住。 | 用户体验。 | 主窗口（mainWindow）关闭时：若 cabinetWindow 存在，主动 `cabinetWindow.close()`（兜底 destroy，和 consoleWindow 策略一致）；或保留电柜窗口，让进程继续运行（根据现有 app.on('window-all-closed') 决策，默认与 consoleWindow 保持一致）。 |

## 10. 验收标准（Acceptance Criteria）
1. 主界面右上角「⚡ 电柜管理」按钮出现在悬浮窗按钮**之前**。
2. 点按钮打开独立电柜管理窗口；主界面播放音乐、连接控台、录屏等主线操作完全不受任何影响。
3. 添加电柜后，开关数量可在 12/18/24/30/36 间选择，每行 6 个按钮，单击切换可发送 UDP。
4. 同一 IP 的两个批次设备（新/老）任意一个存在时，实际点灯都能响应。
5. 发送 1000ms 没收到回传 → 按钮边框闪黄框 2 秒，按钮状态不变。
